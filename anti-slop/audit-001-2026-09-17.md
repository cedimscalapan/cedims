# CEDIMS antislop audit — 001 — 2026-09-17

Mode 2 (After): audit only. Nothing in the codebase has been changed. This report compiles five parallel audits (one per antislop task skill) run per `docs/ANTISLOP_AUDIT_PROMPT.md`. Each finding below is numbered; tell me which numbers to fix (e.g. "fix 1-18", "fix all HIGH", "fix everything except the copywriting section") and only those get touched. Numbers not mentioned stay untouched.

Priority follows the antislop core's tier mapping: **HIGH** = Hard Gate rule or a real functional/data defect with user impact, **MEDIUM** = Purpose-Gate or a real-but-contained issue, **LOW** = Quality Lock / cosmetic.

## Executive summary

The codebase is materially better than a typical AI-assisted build: no fabricated statistics, no mock dashboard data, no dead nav links, no generic template layout, no fake testimonials anywhere in scope. The two things worth fixing first:

1. **Ambiguous "no data" vs. "0% / fully compliant" signal**, recurring in the compliance heatmap, the analytics page, monitoring (district + school), and the academic calendar manager (findings 1, 5, 6, 7, 8). This is the single risk this system can least afford: a network hiccup or a genuinely-empty week must never look like "nothing outstanding" to a District Supervisor.
2. **Every compliance status chip in the app fails WCAG AA contrast** (findings 1-2), because the same "text color on its own low-opacity tint" pattern is reused everywhere. One fix at the shared source (`app.css` `.status-*` classes + `StatusBadge.svelte` + the two `getComplianceClass`/`getComplianceBgClass` helpers) resolves most of it at once.

Three **real functional bugs** turned up that aren't slop at all, just bugs worth knowing about regardless of what you decide on the rest of this list: the Academic Calendar Manager shows 10 blank placeholder weeks for Term 2/3 instead of the real weeks 14-39 (#19); the QR-verification page's "Sign In" button links to a route that doesn't exist, `/login` instead of `/auth/login` (#20); and a chevron button in the teacher-cluster drill-down is both hover-only and has no click handler at all, so it's inert for every user regardless of device (#22).

The **copywriting audit is 63% em dashes** (23 of 37 findings) — the app's house punctuation style, most heavily concentrated in the Gabay chatbot's canned replies (`src/lib/utils/chatbot.ts`, ~90 occurrences, one bundled finding at #55). The **code-comment audit found zero HIGH findings** — no patch-scripts, nothing functional — just decorative banners and step-by-step narration that's safe to clean up broadly.

One cross-cutting technical note surfaced incidentally, not tied to a specific antislop rule: a mojibake encoding bug ("â€”" instead of "—") appears in a few code comments and, per the code-comment agent, also in some non-comment UI strings (`ComplianceHeatmap.svelte`, several `<title>` tags) — see the note after #109 and the appendix.

Counts: **143 findings** — 40 HIGH, 61 MEDIUM, 42 LOW. (Section-level agent self-summaries occasionally undercounted their own bullets; the numbers below are a direct recount against each agent's findings text, which is ground truth over its summary line.)
